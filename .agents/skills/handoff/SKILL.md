# 인수인계 노트 작성

`docs/notes/handoff.md` 를 **덮어씁니다** (누적하지 않습니다 — 최신 상태 하나만 유지).
다음 세션은 이 파일 하나만 읽고 이어받을 수 있어야 합니다.

## 1. 상태 수집

먼저 실제 상태를 확인합니다. 대화 기억에만 의존하지 않습니다.

- `git status --short` — 변경·추가·삭제된 파일
- `git diff --stat` 과 `git diff` — 무엇이 어떻게 바뀌었는지
- `git log --oneline -5` — 이 세션에서 커밋한 것이 있는지
- 이 세션에서 실제로 실행한 빌드·테스트 명령과 그 결과

## 2. 작성

`docs/notes/handoff.md` 를 아래 형식으로 씁니다.

```markdown
# 인수인계

**마지막 갱신**: YYYY-MM-DD
**브랜치**: <브랜치명>

## 하려던 것
<한두 문장. 배경 없이도 이해되게.>

## 바꾼 것
- `경로/파일.ts` — 무엇을 왜
- ...

## 검증됨
실제로 실행해서 통과한 것만 명령과 함께 적습니다.
- `pnpm test` — 통과 (24 passed)
- ...

## 미검증
바꿨지만 확인 안 한 것. **여기 있는 건 다음 세션이 직접 확인해야 합니다.**
- 에러 처리 분기 — 테스트 없음
- ...

## 다음 단계
- [ ] 구체적으로 무엇부터
- [ ] ...

## 막힌 것 / 미해결 질문
- ...

## 함정
다음 사람이 모르면 시간을 버릴 내용. 없으면 이 섹션을 지웁니다.
- ...
```

## 3. 원칙

- **"검증됨" 과 "미검증" 을 절대 섞지 않습니다.** 이 구분이 이 문서의 존재 이유입니다. 돌려보지 않은 것을 검증됨에 적으면 다음 세션이 깨진 코드 위에 쌓습니다.
- 파일 경로는 실제 경로로 씁니다. "인증 쪽 고침" 이 아니라 `src/auth/session.ts` 로 씁니다.
- 다음 단계는 실행 가능한 단위로 씁니다. "마무리" 가 아니라 "`login()` 실패 케이스 테스트 추가" 로 씁니다.
- 이미 커밋된 내용은 짧게 요약만 하고 git 이 기억하게 둡니다. 아직 커밋 안 된 작업 트리 상태에 분량을 씁니다.
- 비밀값·토큰·`.env` 내용을 옮겨 적지 않습니다.
- `docs/notes/` 가 없으면 만듭니다.

## 4. 보고

파일을 쓴 뒤, 검증됨/미검증 항목 수와 다음 단계 첫 줄을 사용자에게 한 줄로 요약해 알립니다.
