# AGENTS.md 채우기

`AGENTS.md` 의 `## 프로젝트` 와 `## 명령어` 섹션에 남아 있는 `<채우기>` 를 실제 값으로 바꿉니다.
**`AGENTS.md` 외의 파일은 수정하지 않습니다.**

## 1. 탐지

리포지토리 루트에서 아래를 확인합니다. 여러 개가 잡히면 전부 반영합니다 (모노레포·다중 언어 가능).

| 발견한 파일 | 읽을 것 |
| --- | --- |
| `package.json` | `scripts` 전체, `packageManager` 필드, 주요 의존성 (프레임워크 판별용) |
| `pnpm-lock.yaml` / `yarn.lock` / `bun.lockb` / `package-lock.json` | 패키지 매니저 확정 |
| `Cargo.toml` | `[package]` 이름, 워크스페이스 여부, 바이너리/라이브러리 |
| `pyproject.toml` | 빌드 백엔드, `[project.scripts]`, ruff/pytest/mypy 설정 유무 |
| `uv.lock` / `poetry.lock` / `requirements.txt` | 파이썬 패키지 매니저 확정 |
| `go.mod`, `Makefile`, `justfile`, `Taskfile.yml` | 해당 러너의 타깃 목록 |
| `index.html` 만 있고 위가 없음 | 빌드 도구 없는 정적 사이트 |

**추측하지 않습니다.** `package.json` 에 `test` 스크립트가 없으면 테스트 칸은 `없음` 으로 둡니다. 있지도 않은 명령을 적는 것이 빈칸보다 나쁩니다.

패키지 매니저는 lock 파일로 판정합니다. lock 파일이 없으면 `packageManager` 필드를 보고, 그것도 없으면 `npm` 으로 둡니다.

## 2. 검증

표에 적을 명령 중 **부작용이 없는 것만** 실제로 실행해 동작을 확인합니다.

- 실행해도 되는 것: 타입 체크, 린트, 테스트, `cargo check`, `--help`, `--version`
- 실행하지 않는 것: 설치, 개발 서버(블로킹), 빌드(오래 걸림), 배포

명령이 실패하면 표에는 그대로 적되, **실패했다는 사실과 출력을 사용자에게 보고합니다.** 실패를 숨기고 성공한 것처럼 채우지 않습니다.

## 3. 작성

`AGENTS.md` 를 열어 아래만 바꿉니다.

- `## 프로젝트` 의 한 줄 설명 / 스택 / 진입점
- `## 명령어` 표의 각 행

규칙:

- 명령은 백틱으로 감싸고, 프로젝트 루트에서 그대로 붙여넣어 실행 가능한 형태로 씁니다.
- 해당 없는 항목은 `없음` 으로 적습니다. `<채우기>` 를 남기지 않습니다.
- 단일 테스트 칸에는 파일 하나를 돌리는 실제 형태를 적습니다. 예: `pnpm vitest run src/foo.test.ts`, `pytest tests/test_foo.py`, `cargo test foo`
- 여러 스택이 섞여 있으면 행을 나누고 `(web)`, `(api)` 처럼 어느 쪽인지 표시합니다.
- `> 위 세 줄과 아래 명령어 표는 ...` 로 시작하는 안내 인용문은 지웁니다. 채운 뒤에는 필요 없습니다.

## 4. 보고

사용자에게 다음을 알립니다.

- 탐지한 스택과 패키지 매니저, 그렇게 판단한 근거 (어떤 파일을 봤는지)
- 실제로 실행해 확인한 명령과 그 결과
- 확인하지 못한 채로 적은 명령 (설치·빌드·개발 서버 등)
- 채우지 못하고 `없음` 으로 남긴 항목
